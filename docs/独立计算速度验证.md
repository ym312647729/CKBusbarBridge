# 独立计算速度验证

2026-11-18，在当前开发机的 20 个逻辑核心上离线验证。最大并发为 `max(1, 逻辑核心数 - 3)`，本机为 17。几何和实体检查共用有界工作池；已知需要桥体时，在上游规划阶段提前准备线程。下表保留首次并行优化的结果，后续任务分配优化见本文后半部分。

使用默认面对面常规参数、343 个部件、125 mm 绝缘距离。每轮重新创建独立计算会话，先计算柜体，再计算完整桥体；单线程和最大并发交替执行三轮。完整预览时间包括 DLL 通信、网格生成、实体净距与干涉检查、网格序列化和返回，不含 SolidWorks 视口绘制。

| 轮次 | 单线程完整预览 | 最大并发 17 完整预览 |
| --- | ---: | ---: |
| 1 | 4283 ms | 2194 ms |
| 2 | 4360 ms | 2204 ms |
| 3 | 4351 ms | 2357 ms |
| 中位数 | 4351 ms | 2204 ms |

中位耗时缩短约 49.3%。每轮逐项比较几何签名、安装矩阵和完整绝缘/干涉报告，结果完全一致：零实体干涉、最小对地净距 125 mm。

另一次正常运行中，从进入到首次完整预览（包含柜体计算与规划）为 3760 ms；相同输入重复预览为 226、239 ms。重复计算可以复用已完成的实体检查，修改绝缘距离后必须重新检查。以上为本机离线数据，不能代表 SolidWorks 窗口的实际绘制耗时。

面对墙搜索期间，路径 Worker 最多使用总预算减一的并发数，参数预览使用一路，避免两个计算池同时占满逻辑核心。总搜索时限仍为一分钟，多线程用于减少首个结果和每次预览的等待时间。

验证入口（参数中的路径应指向同一构建目录）：

```powershell
CKBusbarBridge.Computation.Bench.exe <构建目录>\Worker <构建目录>\CKBusbarBridge.WebTest.exe --compare
node tools/Test-ParallelClearance.mjs
```

第二项同时覆盖相间不足、对地不足、实体干涉和空分区，对比 1、2、3、17 个分区，保证分区合并不漏检。

## 后续任务分配优化

优化前基准为提交 `058745e` 的独立计算运行目录。前后均使用最大并发 17、默认面对面常规参数和 343 个部件；每轮重新建立计算会话，先准备柜体，再计时完整桥体。两种版本交替顺序运行，第二轮先运行优化版，减少顺序影响。

| 轮次 | 优化前 | 本轮优化后 |
| --- | ---: | ---: |
| 1 | 2034 ms | 1247 ms |
| 2 | 2425 ms | 1219 ms |
| 3 | 1939 ms | 1243 ms |
| 中位数 | 2034 ms | 1243 ms |

本轮中位耗时再缩短约 39%。每轮逐项核对显示与交互网格的全部坐标、四边面、三角面、棱边、安装矩阵、实例身份、外观、尺寸及完整实体检查报告，均与优化前一致。

主要调整：

- 基架先计算安装基准，确定安装和盖板边界后只生成最终实体，消除生成后丢弃的首遍实体。
- 已求解的基准带完整输入身份在工作线程之间传递；最终生成不用重复读取和求解同一组模板。基准和形状缓存有数量及内存上限。
- 基架等关键任务优先，并尽量复用已有模板的线程；铜排计算与结构安装准备并行。
- 大场景使用全部 17 路检查任务。相间、对金属和干涉分别用原子队列动态领取每批 32 对对象，保留原始对号和稳定排序；不具备共享内存时保留静态分区。
- 网格整理与实体检查重叠执行；完整检查结束后才允许返回预览。
- 同一响应中的 686 个显示/交互实例只传送 160 份唯一网格，复用 526 次引用。坐标沿用原 Float32 精度、索引沿用 Uint32，使用二进制编码传输，不重新离散。视口不再接收未使用的逐体来源副本；用于草稿保存的完整项目快照仍保留。
- 同时核对旧文本协议兼容、原视口冻结帧冷启动/缓存引用、非法报文拒绝，以及计算进程的退出与回收。

另一次正常运行：首次完整计算 1308 ms，相同输入重复计算 209、220 ms；从进入到首次完整预览（包含柜体与规划，不含视口冻结帧构造和绘制）2604 ms。单路与 17 路对比的完整计算中位数分别为 3481、1303 ms，结果一致。柜前和柜后向墙的完整实体检查也保持零干涉及至少 125 mm 对金属净距。
